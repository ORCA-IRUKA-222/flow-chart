# フローチャート

PC・タブレット・スマホで使える、無限キャンバスのフローチャート作成アプリです。
GitHub だけで動き（アプリは GitHub Pages、データは GitHub の非公開リポジトリ）、PC を付けておく必要はありません。

- 上下左右どこまでも広がるキャンバス（パン・ズーム）
- タブレットでペン書き →「整形 OCR」ボタンで、手書きの図形・矢印・文字がきれいなフローチャートになる
- ノードの端の ○ をドラッグするだけで線を引ける。ドラッグで移動、角の ■ で大きさを変更
- ノードはいくつでも作れる（画面外のものは描画を省くので、数千個でも軽く動く）
- データはまず端末に保存し、GitHub（または自分の同期サーバー）を通して他の端末と同期
- ボード（空間）を複数作って切り替え・名前変更・削除

## はじめかた（GitHub だけで完結・PC 不要）

アプリ本体は GitHub Pages、データは GitHub の非公開リポジトリに置きます。PC を付けておく必要はありません。

### 1. アプリを公開する（最初に1回）

1. このリポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にする
2. `main` ブランチに変更が入ると、`.github/workflows/pages.yml` が `public/` を公開する（Actions タブから手動でも実行できる）
3. 公開先: `https://orca-iruka-222.github.io/flow-chart/`

### 2. データ用のリポジトリとトークンを作る（最初に1回）

1. GitHub で新しいリポジトリを **Private（非公開）** で作る（名前は例: `flow-chart-data`。中身は空でよい）
2. [Fine-grained token の作成画面](https://github.com/settings/personal-access-tokens/new)で次のように作る
   - Repository access: 「Only select repositories」で、1 のリポジトリだけを選ぶ
   - Permissions の「Add permissions」を押し、検索欄に `Contents` と入れてチェック → 追加された Contents の行で「Read-only」を **「Read and write」** に変える（Metadata: Read-only は自動で付くのでそのまま）
   - 有効期限は好みで（切れたら作り直して、各端末で入れ直す）
3. 表示されたトークン（`github_pat_…`）を控えておく

このトークンでできるのは、そのデータ用リポジトリの読み書きだけです。

### 3. 各端末で開いて設定する

1. タブレット・スマホ・PC のブラウザで `https://orca-iruka-222.github.io/flow-chart/` を開く
2. タブレット・スマホは、共有メニューの「ホーム画面に追加」でアプリとして登録する（iPhone / iPad は Safari から）
3. 右上の同期表示（または ☰ →「同期の設定」）→「GitHub に保存」を選び、リポジトリ名（例: `orca-iruka-222/flow-chart-data`）とトークンを入れて「保存」

これで、どの端末で編集しても GitHub に保存され、他の端末に反映されます。

- アプリを開いている間、約10秒ごとに GitHub を確認し、編集は2秒ほどで書き込みます（数秒〜十数秒の遅れで同期）
- 電波がない間も編集でき、つながったときに自動で送ります。一度開いたアプリは電波がなくても開けます
- 2台で同時に編集しても、ノード・線ごとに新しい方を残して合成するので、どちらかの変更が丸ごと消えることはありません
- 設定する前にその端末で作っていたボードも、GitHub に送られます
- データ用リポジトリには `boards/<ID>.json` として保存され、変更のたびにコミットされます（GitHub 上で履歴をたどれます）

## そのほかの使い方

| 使い方 | 内容 |
| --- | --- |
| この端末だけ | 同期しない。設定なしで GitHub Pages のアドレスを開くとこれになる |
| 自分の同期サーバー | PC などで `npm start` したサーバーと、即時に同期する（下記） |

> **注意:**「この端末だけ」のデータはブラウザの保存領域に入っています。ブラウザのデータを消去すると消えます。
> iPhone / iPad では、ホーム画面に追加せずに Safari で使っていると、しばらく開かなかったときに消されることがあります。
> 大事なボードは GitHub に同期するか、「書き出し」で JSON に保存してください。

### 自分の同期サーバー（PC などで動かす）

Node.js 18 以上が必要です。

```bash
npm install
```

```bash
npm start
```

起動すると、次のように表示されます。

```
フローチャートアプリを起動しました
  この PC から:        http://localhost:8787
  タブレットなどから:  http://192.168.x.x:8787
```

同じ Wi-Fi の端末から `http://192.168.x.x:8787` を開けば、同期先は自動でこの PC になります（変更はすぐ反映）。
データは `data/` フォルダに JSON で保存されます。このサーバーは同期するときだけ動いていればよく、止まっている間の変更は各端末にたまり、次につながったときに送られます。

GitHub Pages のアプリ（https）から使う場合は、ブラウザの制限で http のサーバーには接続できないため、サーバーを https で公開してください。
例えば [Tailscale](https://tailscale.com/) なら、PC で `tailscale serve --bg 8787` を実行し、表示された `https://〜.ts.net` を「自分の同期サーバー」に入れます。

## 使い方

| やりたいこと | PC | タブレット・スマホ |
| --- | --- | --- |
| ノードを追加 | 空白をダブルクリック / 上部の ＋ ボタン | 空白をダブルタップ / ＋ ボタン |
| 文字を編集 | ダブルクリック / Enter | ダブルタップ / 下のバーの ✎ |
| 移動 | ドラッグ（Alt を押すと吸着なし） | 指やペンでドラッグ |
| 線を引く | ノードの ○ を別のノードへドラッグ | 同じ |
| 線の先に新しいノード | ○ を空白へドラッグ / ○ をクリック / Tab | ○ を空白へドラッグ / ○ をタップ |
| 画面の移動 | 空白をドラッグ / ホイール | 指 1 本でドラッグ |
| 拡大・縮小 | Ctrl + ホイール / トラックパッドのピンチ | 指 2 本でピンチ |
| 拡大率を固定 | 左下の鍵ボタン / `L` | 左下の鍵ボタン（固定中は指 2 本で移動だけ） |
| 複数選択 | Shift + クリック / Shift + 空白ドラッグで範囲選択 | — |
| 削除 | Delete / 下のバーのゴミ箱 | 下のバーのゴミ箱 |
| 元に戻す / やり直す | Ctrl+Z / Ctrl+Shift+Z | 左下の ↶ ↷（手書き・消しゴム・整形も戻せる） |

選択すると下にバーが出て、形（処理・開始/終了・分岐・入出力など）、色、線の種類（カギ線・直線）、矢印の向きを変えられます。

その他のキー: `V` 選択、`T` 文字ペン、`G` 図形ペン、`E` 消しゴム、`P` 文字ペン⇄図形ペン、`F` 全体表示、`R` 整形、`Ctrl+D` 複製、矢印キーで少しずつ移動。

### ツール

| ツール | できること |
| --- | --- |
| 選択（V） | ノードを動かす・つなぐ・編集する。ペンで囲むと範囲選択（マウスは Shift + ドラッグ）、指でドラッグすると画面の移動 |
| 文字ペン（T） | 文字を書く（黒）。整形すると文字になる |
| 図形ペン（G） | 四角・角丸・ひし形・楕円・平行四辺形の枠と、つなぐ線を書く（青）。整形すると図形と線になる |
| 消しゴム（E） | なぞった手書き・ノード・線を消す。なぞり始めに最初に触れたものの種類（手書き、またはノードと線）だけが消える |

ペンを使い始めると、指は画面の移動・拡大（2本指）専用になり、画面に触れた手のひらでは描かれません。
手書きは常にノードより手前に表示されます。

### スタイラスペンのサイドボタン

| ボタン | 動き |
| --- | --- |
| 1つ目のボタン（右クリックにあたるボタン、または PageDown キーを送るボタン） | 文字ペン ⇄ 図形ペン を切り替える |
| 2つ目のボタン（中クリックにあたるボタン、または PageUp キーを送るボタン） | 消しゴムにする / もう一度押すと元のペンに戻る |
| 消しゴム側のペン先（Surface ペンなど） | 押し当てている間だけ消しゴム |

Redmi / Xiaomi のスマートペンのように、サイドボタンを PageDown / PageUp キーとして送るペンにも対応しています。
ペン先を画面から少し浮かせた状態でボタンを押してください。押すと画面下に「文字ペンにしました」などと表示されます。
役割が逆だったときは、ボード一覧の下の「ペンのボタンを入れ替える」にチェックを入れてください。
何も割り当てられていないボタンを押したときは、そのボタンの番号が表示されます。
ボタンが反応しないときは、ボード一覧の下の「ペンのボタンを確認」で、押したときにブラウザに何が届いているかを確認できます（タブレット本体の機能がボタンを使っていると、ブラウザには届きません）。

### 手書きで描いて整形する

1. 図形ペンで、四角・角丸・ひし形・楕円・平行四辺形を描き、図形どうしを線でつなぐ（矢じりは書いても書かなくても可。書いた側が矢印の先になります）
2. 文字ペンで、図形の中に文字を書く。線の近くに書いた文字は線のラベル（「はい」「いいえ」など）、どこにも属さない文字はテキストになります
3. 「整形 OCR」を押す

整形すると、図形はグリッドに合わせてサイズがそろい、近いノードは中心線がそろうように並びます。
既存のノードの間に図形ペンで線を書いたり、既存のノードの中に文字ペンで書いたりしても認識します。
認識できなかった線や文字は手書きのまま残るので、書き直してもう一度押せます。
元に戻す（↶）で、整形の前の手書きに戻せます。

「整形」の右の ▾ から、整形する範囲を選べます。

| 種類 | 内容 |
| --- | --- |
| すべて整形 | 図形・線・文字をまとめて清書（ボタンを押したときと同じ。キーは `R`） |
| 図形だけ整形 | 図形ペンの枠と線だけを清書し、文字ペンの手書きは残す（キーは `Shift+R`）。先に図の形を整えてから文字を書きたいときに |
| 文字だけ整形 | 文字ペンの手書きだけを文字にし、図形ペンの手書きは残す |

選択ツールでペンで囲むと、囲んだ範囲の手書きだけを整形できます（下のバーの「整形」「図形だけ」「文字だけ」）。何も選んでいなければ、すべての手書きが対象です。

残した手書きは、あとで「すべて整形」などを押すと変換されます。図形だけ整形したあとにノードの上に残った文字も、そのノードの文字になります。

### 読み間違いを直す

ノード（または線）を選んで「直す」を押すと、次の方法で直せます。

- **読み取りの候補**: 整形したときに文字認識が出した、ほかの候補から選ぶ（その端末で整形した直後から、アプリを開いている間だけ）
- **キーボードで入力**: 文字を打ち直す
- **手書きで書き直す**: 文字を消して文字ペンにするので、ノードの中に書いて「整形」を押す

### 大きさをそろえる

ペンで囲んで複数のノードを選び、下のバーの「大きさをそろえる」を押すと、選んだノードがすべて同じ大きさになります。
幅は「いちばん長い文字が1行に入る幅」、高さは「その幅で全部の文字が入る高さ」です（大きすぎるノードは小さくなります）。
ノードが1つだけのときは「文字に合わせる」になり、そのノードを文字がちょうど入る大きさにします。

## 文字認識について

図形と矢印の判定は端末の中で行います。文字の認識は次の順に試します。

1. ブラウザ内蔵の手書き認識（Chrome の一部環境で利用可能。端末の外に送りません）
2. 同期サーバー経由で Google の手書き入力サービスに筆跡（座標の列）を送って認識
3. 同期サーバーがない（GitHub 同期・この端末だけ）か、つながらないときは、端末から直接 Google の手書き入力サービスに送って認識

2・3 を使うとき、筆跡データが Google に送られます。どれも使えないときは文字は手書きのまま残ります（図形と線の整形はできます）。
`HANDWRITING_ENDPOINT` で同じ形式の別サービスに差し替えられます。

## 設定（環境変数）

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `PORT` | `8787` | ポート番号 |
| `HOST` | `0.0.0.0` | 待ち受けるアドレス（`127.0.0.1` にすると、この PC からのみ） |
| `DATA_DIR` | `./data` | ボードの保存先 |
| `FLOW_TOKEN` | なし | 設定すると、開くときに合言葉が必要になります |
| `HANDWRITING_ENDPOINT` | Google 手書き入力 | 文字認識サービスの URL |

例:

```bash
FLOW_TOKEN=好きな合言葉 PORT=3000 npm start
```

### インターネットに公開するとき

同期サーバーをインターネットに公開する場合（Tailscale 以外の方法）は、必ず `FLOW_TOKEN` を設定し、HTTPS（リバースプロキシや Cloudflare Tunnel など）経由で公開してください。

## 同期のしくみ

GitHub 同期:

- 各端末は `boards/` の一覧を定期的に確認し（変化がなければ軽い 304 応答で済む）、変わったボードだけ読み込みます。
- 書き込みが他の端末とぶつかったら、最新を読み込んで合成してから書き直します。
- 削除したボードは `boards/_deleted.json` に記録し、古い端末から復活しないようにします。

自分の同期サーバー:

- 変更は「ノード / 線ごとの操作」として WebSocket で送られ、サーバーが他の端末へ配ります。
- 各要素は論理時刻で「後から変更した方が勝つ」ので、届く順番が違っても全端末が同じ状態になります。
- 送信待ちの変更と、開いたボードの内容は端末（IndexedDB）にも保存されます。オフラインでも編集でき、再接続時に自動で送られます。
- 同期先を設定した（変えた）とき、その端末にあるボードはまるごと同期先へ送られます。オフライン中のボード作成・名前変更・削除も、つながったときに送られます。
- 削除したボードは記録され、古い端末から送られても復活しません。
- 「書き出し」で JSON に保存し、「読み込み」で新しいボードとして取り込めます（バックアップ用）。
